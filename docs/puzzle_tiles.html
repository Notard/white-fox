얼음, 무너지는 칸, 스위치와 문, 계단

새 칸 네 가지로 퍼즐을 깊게 합니다. 칸이 놓이는 바닥과 보석·시작 같은 물건을 따로 저장하고, 무너진 칸과 열린 문처럼 판 상태가 바뀌는 것까지 이동 규칙과 맵툴 검증이 함께 계산합니다.

새 칸

칸별 규칙

얼음

I
🦊→멈춤
  • 얼음 칸에 들어서면(걷기·점프 착지 모두) 그 방향으로 한 칸씩 계속 미끄러집니다.
  • 얼음이 아닌 칸에 들어서면 그 칸에서 멈춥니다.
  • 앞이 장애물·닫힌 문·더 높은 칸이면 지금 얼음 칸에서 멈춥니다.
  • 앞이 구멍·맵 밖이면 미끄러져 떨어집니다.
  • 미끄러지며 지나간 칸의 보석은 먹습니다. 미끄러지는 동안은 조작할 수 없습니다.

무너지는 칸

C
밟고 떠나면
  • 밟고 서 있을 때는 땅과 같습니다.
  • 다른 칸으로 걸어가거나 뛰어 떠나면 무너져 구멍이 됩니다.
  • 제자리에서 부딪히거나 제자리 점프를 하는 것은 떠난 게 아닙니다.

스위치

W
밟으면→열림
  • 스위치 칸에 서면(걷기·착지·미끄러져 멈춤) 판의 모든 문이 열립니다.
  • 한 번 열린 문은 계속 열려 있습니다.

문

D
닫힘 = 장애물
  • 닫힌 문은 장애물과 같습니다. 걸어서 못 들어가고, 착지할 수 없으며, 점프로 넘을 수는 있습니다.
  • 열린 문은 땅과 같습니다. 문이 땅으로 내려가는 모습으로 열립니다.

계단

T
124걸어서 오름
  • 계단 칸과 바로 옆 칸 사이는 높이 차와 상관없이 걸어서 오르내립니다.
  • 계단 모양은 옆 칸 중 가장 높은 쪽을 향합니다 (보기용).
파일 형식

스테이지 파일 버전 3: 바닥과 물건 분리

rows는 바닥만, 새 items는 보석·시작만 담습니다. 그래서 얼음이나 무너지는 칸 위에도 보석을 놓을 수 있습니다.

{
  "version": 3,
  "name": "미끄러운 연못",
  "id": "미끄러운 연못",
  "width": 5, "height": 4,
  "rows":   [ "..D..", ".III.", "W.C..", "....." ],
  "items":  [ "..G..", "...G.", ".....", "S...." ],
  "floors": [ "11111", "11111", "11111", "11111" ]
}
층기호
rows 바닥. 땅 · O 구멍 · # 장애물 · I 얼음 · C 무너짐 · W 스위치 · D 문 · T 계단
items 물건. 없음 · G 보석 · S 시작
floors 층1~9 (그대로)

버전 1·2 파일은 읽을 때 rows의 G·S를 items로 옮기고 그 자리 바닥은 땅으로 둡니다. 맵툴에서 저장하면 버전 3이 됩니다. 보석·시작은 구멍·장애물·문 위에 둘 수 없습니다(검증 오류).

검증

"한 판에 모두 모을 수 있나"

  • (칸, 바라보는 방향, 문 열림, 무너진 칸들, 모은 보석들) 상태를 넓이 우선으로 탐색해서, 보석을 모두 모은 상태에 닿는지 봅니다. 게임과 같은 MoveRules를 씁니다.
  • 어떤 경로로도 못 먹는 보석은 지금처럼 빨간 테두리로 표시합니다.
  • 보석마다 갈 수는 있지만 무너지는 칸 때문에 한 번에 다 모을 수 없으면 "한 판에 모두 모을 수 없음" 오류를 냅니다.
  • 맵이 너무 복잡해 탐색이 정해진 한도(상태 50만 개)를 넘으면 경고만 내고 저장은 허용합니다.

게임 화면

예제 스테이지 6~9

테스트가 칸마다 움직여 보며 찍은 화면입니다. 왼쪽 위부터 미끄러운 연못(얼음에서 미끄러져 보석을 먹고 바위 앞에서 멈춤), 무너지는 다리(떠난 칸이 떨어지는 중), 잠긴 보물(분홍 스위치를 밟아 문이 내려감), 돌계단 언덕(계단으로 4층 고원에 오름).
