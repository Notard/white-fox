Unity 맵툴과 JSON 맵 불러오기

Unity 에디터 안에서 칸을 칠해 스테이지 맵을 만들고 JSON 파일로 저장하면, 게임이 스테이지 1부터 차례로 불러와 타일맵을 만듭니다. 지금은 맵이 BoardLayout.asset 하나에 고정되어 있는데, 이것을 스테이지 파일 기반으로 바꾸는 작업입니다.

작성 2026-10-06대상 FoxGame (Unity 6000.5, URP)상태 구현 완료 · 테스트 25개 통과

만드는 것

에디터 창 FoxGame › 맵툴. 스테이지를 추가·정렬하고, 붓으로 칸을 칠하고, 검증해서 저장합니다.

바뀌는 것

게임이 Resources/Stages/stage_NN.json을 순서대로 읽어 스테이지 1 → n을 진행합니다.

지키는 것

이동 규칙은 게임과 맵툴이 같은 코드를 씁니다. 맵툴이 "클리어 가능"이라 하면 게임에서도 됩니다.

    확정된 결정
    
  
    이렇게 만듭니다
    
  
    
    
    
      
    맵 크기는 맵툴에서 지정한 그대로
    
      
    가로·세로를 각각 2~16칸으로 정할 수 있습니다. 카메라가 보드 크기에 맞춰 자동으로 물러나서 어떤 크기든 화면에 다 들어옵니다.
    
    
    
    
    
      
    보석 개수는 자유
    
      
    1개 이상이면 됩니다. 화면 왼쪽 위 배지는 그 스테이지의 보석 수를 보여 줍니다.
    
    
    
    
    
      
    맵은 스테이지 1 → n 순서로 진행
    
      
    게임은 스테이지 1부터 시작합니다. 클리어하면 "다음 스테이지"로 넘어가고, 마지막 스테이지를 깨면 "처음부터"를 고를 수 있습니다. 떨어지면 같은 스테이지를 다시 합니다. 스테이지 추가·삭제·순서 변경은 맵툴에서 합니다.
    
    
    
    
    
      
    JSON은 맵툴에서만 고침
    
      
    파일은 Assets/Resources/Stages에 두고 게임 안에 묶어서 빌드합니다. 빌드한 폴더에서는 고칠 수 없습니다. 에디터에서 스테이지 JSON을 더블클릭하면 텍스트 편집기 대신 맵툴이 열립니다.

    파일 형식
    
  
    JSON 스테이지 파일
    
  
    칸은 지금의 BoardLayout과 같은 기호 문자열로 저장합니다. 사람이 고치는 파일은 아니지만, 버전 관리에서 바뀐 칸을 알아보기 쉽습니다. rows[0]이 화면에서 가장 먼 줄입니다.
    

    {
  "version": 1,
  "name": "첫 번째 숲",
  "width": 4,
  "height": 4,
  "rows": [
    "G.#G",
    ".O.G",
    "#..O",
    "S.G."
  ]
}
    
  
    
    . 땅
    O 구멍
    # 장애물
    G 보석 (땅 위)
    SS 시작 (땅 위)
  
    
  
    version은 나중에 칸 종류가 늘어날 때 옛 파일을 구분하려고 둡니다. 파일이 깨져 있으면 어느 줄 몇 번째 글자가 틀렸는지 오류로 알려 줍니다.
    

    


    
  
    검증 규칙
    
  
    저장 전에 확인하는 것
    
  
    
    
    
      
    규칙어기면이유
    
      
        
    시작 위치가 정확히 1개저장 불가여우가 놓일 곳이 필요합니다.
    
        
    보석이 1개 이상저장 불가보석이 없으면 클리어 조건이 없습니다.
    
        
    모든 보석에 갈 수 있음저장 불가클리어할 수 없는 스테이지를 막습니다. 못 가는 보석은 빨간 테두리로 표시합니다.
    
        
    크기 2×2 ~ 16×16선택 불가입력 범위를 이 안으로 제한합니다.
    
          
    
    
  
    
  
    "갈 수 있음"은 (칸, 바라보는 방향) 상태를 넓이 우선 탐색으로 계산합니다. 걷기는 한 칸 이동이고, 장애물에 부딪히면 방향만 바뀝니다. 점프는 바라보는 방향으로 두 칸 앞에 착지하며, 그 칸이 장애물이면 제자리에 머뭅니다. 구멍이나 맵 밖으로 가는 이동은 실패로 봅니다. 이 계산은 FoxController가 쓰는 MoveRules를 그대로 호출합니다.
    

    


    
  
    
    
    코드 변경
    
    
    새로 만들고 고칠 파일
    
  
    
  
    
    
    
      
    파일내용
    
      
        
    Scripts/Map/MapData.cs새로스테이지 한 장의 데이터(이름, 크기, 칸 기호). 칸 종류·시작·보석 조회, 크기 변경. BoardLayout을 대신합니다.
    
        
    Scripts/Map/MapJson.cs새로JSON 읽기·쓰기와 형식 오류 메시지.
    
        
    Scripts/Map/MoveRules.cs새로걷기·점프 결과 계산(순수 C#). 게임과 검증이 함께 씁니다.
    
        
    Scripts/Map/MapValidator.cs새로검증 규칙과 도달 가능성 탐색.
    
        
    Scripts/Map/StageLibrary.cs새로Resources/Stages의 스테이지 목록과 불러오기, 현재 스테이지 번호(재시작해도 유지).
    
        
    Scripts/Game/CameraFit.cs새로보드 크기에 맞춰 카메라 거리를 자동 조정.
    
        
    Editor/MapEditorWindow.cs새로맵툴 창. 스테이지 목록(추가·복제·삭제·순서), 붓, 칸 칠하기, 크기 변경, 저장·되돌리기, 실행 취소, 씬에 미리보기, 이 스테이지로 플레이. JSON 더블클릭 시 맵툴로 열기.
    
        
    Board.cs고침MapData로 보드를 만듭니다.
    
        
    GameManager.cs / GameUI.cs고침현재 스테이지를 불러오고, 스테이지 번호 표시, 클리어 후 "다음 스테이지" / 마지막이면 "처음부터".
    
        
    FoxController.cs고침이동 판정을 MoveRules로 옮깁니다. 동작은 그대로입니다.
    
        
    BoardLayout.cs / .asset정리내용을 stage_01.json으로 옮긴 뒤 삭제합니다.

      2. 
    
    2. 게임이 스테이지를 불러오게 전환
      
      
      Board, GameManager, FoxController가 MapData를 쓰도록 고치고, 카메라 자동 맞춤과 스테이지 진행 UI를 넣습니다.
      
      
      확인: 기존 PlayMode 테스트 10개가 그대로 통과. 스테이지 1 클리어 → 스테이지 2(다른 크기)로 넘어가는 테스트와 화면 캡처.
      3. 
    
    3. 맵툴 창
      
      
      메뉴 FoxGame › 맵툴. 왼쪽 스테이지 목록과 붓(단축키 1~5), 가운데 칸 그리드(누르거나 끌어서 칠하기), 오른쪽 크기·이름·검증·버튼. 실행 취소(Ctrl+Z), 저장 안 한 변경 표시, 다른 스테이지로 옮기거나 닫을 때 저장 확인.
      
      
      확인: 창 화면 캡처, 저장한 스테이지를 다시 열었을 때 같은 맵.
      4. 
    
    4. 미리보기와 바로 플레이
      
      
      씬에 미리보기는 열린 씬의 보드를 이 스테이지로 다시 깔고, 이 스테이지로 플레이는 그 스테이지부터 Play 모드에 들어갑니다.
      
      
      확인: 지정한 스테이지로 시작하는지 테스트.
      5. 
    
    5. 빌드 확인
      
      
      Windows 빌드에 스테이지가 모두 들어가고 순서대로 진행되는지 확인합니다.
      
      
      확인: 빌드 실행 화면 캡처, Player.log 오류 없음.
